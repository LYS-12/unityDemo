# Fox Unity 工程规范

适用版本：Unity 2022.3.62f3c1。自有业务代码位于 `Assets/_Project`，第三方包位于 `Assets/ThirdParty`；TextMesh Pro 和 Unity TutorialInfo 保留工具要求的原路径。

## 资源组织

| 内容 | 目录 |
|---|---|
| FBX、Mesh 资产 | `_Project/Art/Models` |
| 材质 | `_Project/Art/Materials` |
| 模型贴图、RenderTexture | `_Project/Art/Textures` |
| 角色和 UI 图片 | `_Project/Art/Sprites` |
| 动画片段和控制器 | `_Project/Art/Animations` |
| 音乐、音效 | `_Project/Audio/Music`、`_Project/Audio/SFX` |
| 场景 | `_Project/Scenes` |
| 环境、角色、物品和台面预制体 | `_Project/Prefabs` 下对应分类 |
| 动态加载的 UI 预制体 | `_Project/Resources/UI` |
| 物品定义 ScriptableObject | `_Project/Data/Items` |
| 渲染配置 | `_Project/Settings` |
| 战斗原型 | `_Project/Prototypes/Combat` |
| 验证工具与测试 | `_Project/Editor` |

`KitchenAssets` 等来源分组用于避免来源不同但同名的文件相互覆盖。`Variants` 用于保留不同版本的预制体，不代表它们可以直接合并。`LegacyFolders` 只保留拆分前文件夹及其元数据，方便外部文件夹 GUID 引用与回退；不包含迁移出去的业务资源。第三方包内的模型仍保留在原包内部。

使用 Unity Project 窗口移动、重命名资源。批量操作须同时移动 `.meta`，保留 GUID；不要删除 `.meta` 来解决导入问题。移动场景后检查 Build Settings，移动按字符串加载的资源后检查调用路径。不要依据文件名相似或静态引用为零直接删除资源。

## 代码约定

- 一个主要 Unity 组件类型对应一个同名 `.cs` 文件。类型、方法、属性使用 PascalCase；字段、参数和局部变量使用 camelCase。
- Inspector 配置使用 `[SerializeField] private`；需要读取配置时提供只读属性。不要让公共可写字段成为跨模块修改状态的默认入口。
- 更改已有序列化字段名时使用 `[FormerlySerializedAs("原名称")]`，并在 Unity 中验证场景、预制体、继承字段和 ScriptableObject 的值仍有效。
- 输入订阅、事件监听和外部资源必须有对应的退订、禁用和释放。静态状态在 `SubsystemRegistration` 重置，避免关闭 Domain Reload 时保留上一次运行的状态。
- 必需配置缺失时报告组件及原因，停用相关逻辑；不要将空配置视为关卡成功。可选视觉效果和音源允许缺失。
- C# 使用 UTF-8、四空格缩进；现有 `.editorconfig` 提供基础格式约定。注释描述约束、意图和尚未实现的功能，删除 Unity 模板中的空生命周期方法。
- `UnityEditor` 代码放在 Editor 文件夹。不要手改 `GameControl.cs`；修改对应 `.inputactions`，通过其导入设置重新生成。
- 本次保持默认程序集和原有命名空间。后续引入 asmdef 时先确认运行时、编辑器和测试依赖，不要把依赖默认程序集的脚本直接移入独立程序集。
- 不修改第三方源码来迎合自有命名规范；必要补丁须单独记录原因与上游版本。

## 场景和 UI 接入

每个正式场景的 Canvas 挂载 `SceneUIRoot`，由自身 Transform 显式注册 UI 根节点；保持场景内 Canvas、EventSystem 和相机的生命周期一致。业务脚本通过 `UIManager` 管理动态面板。

当前保留 `Resources.Load("UI/" + typeof(T).Name)` 的约定，因此面板类名和预制体文件名必须一致。新增面板后必须运行引用检查；后续可用显式资源注册表解除这项耦合。

通过 `SceneLoader.Load(target, onLoaded)` 切换正式场景，返回值表示请求是否被接受。只在加载完成回调中显示目标关卡面板；加载中拒绝并发请求。加载场景的实际名称是 `LoadScene`，枚举 `LoadingScene` 通过显式映射对应它。

## 日常验证与提交

Unity 菜单提供 `Tools/Fox/Validate Project References` 和 `Tools/Fox/Build Windows Development Player`。编辑场景时先保存自己的工作，再执行引用检查。Test Runner 的 EditMode 中可筛选 `FoxProject.Tests`；其中场景流程测试会实际进入 Play Mode 并操作场景。

`Tools/organize_project.py verify` 根据本次本地备份复核 GUID 与原有资源引用。`snapshot` 和 `migrate` 是本次迁移使用的一次性操作，不应在已经整理过的工程上重复执行。

提交 Assets 中的资源、脚本及 `.meta`，以及 Packages、ProjectSettings、Docs 和工具代码。不要提交 Library、Temp、Logs、Builds、IDE 生成项目和本地备份；项目内 `.gitignore` 已覆盖这些路径。本次没有自动创建提交、推送或修改远端。
